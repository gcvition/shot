# 人手瞄准：一套适配所有场景的方案

本文给 Shot 内部用：回放、假人、研究。不要做成往别的游戏注入鼠标。

准星是转视角（左右 yaw、上下 pitch，单位是度），不是在屏幕上拖像素。鼠标是 `dx, dy`（count）。默认灵敏度下滑 **6000 count** 转一圈。生成器先在「度」里想，再换成 count。不要用窗口像素，也不要再乘帧时间。

---

## 结论：不要按场景各做一套 AI

甩枪、跟枪、压枪、转火、定位、peek、急停点射、扫射转移……看起来很多，对假人来说其实是同一件事的不同衣服：

```text
每一帧：
  1. 看见什么、自己在哪、开了几枪   → 感知
  2. 现在在干哪一类活               → 意图（小状态机）
  3. 算出「这一瞬间想看的方向」B*    → 几何 + 超前 + 减后坐力
  4. 用人手控制器去追 B*             → 甩 or 跟（共用内环）
  5. 决定开不开火                    → 开火门（含急停）
```

**推荐就这一套。** 场景只改第 2、3、5 步的输入，不换第 4 步的「手」。算法当骨架，历史 `.shot` 只填参数和（以后）跟枪残差。不要为 peek 训一个网络、为转火再训一个。

下面先讲场景和这套架构，再附算法 / AI 零件手册。

---

## 0. 共同画面：永远在缩小误差

把准星想成手里的激光笔。每一小步都在缩小：

```text
误差 = 「我想看的方向 B*」−「现在准星的方向」

B* = 从我眼睛指向「焦点」（预瞄点或某个目标，可带一点点超前）
     再减去「枪口已经被后坐力抬走的那部分」
```

- 目标不动、人不动、没有后坐力：就是有头有尾的 A→B（甩枪）。
- 目标在动、人在动、peek 探头：B* 每个瞬间都在变，必须 **闭环**（走一步、看一眼新 B*、再走）。
- 有后坐力：我想看目标，但枪自己先抬了，等于 B* 被加了一个随射击变化的偏移。
- **看不见人时也有 B***：那就是定位 / 预瞄点，不是「准星随便放」。

历史 `.shot` 以后要能重建那一瞬间：**人在哪、焦点在哪、相对速度多少、第几发、后坐力累计多少**。否则模型会把「自己走开了」和「没跟上」搅在一起。

## 1. 瞄准场景全表（都要能接到同一根管子上）

游戏里的「瞄准」很少是单一技能。下面按 **控制器真正吃到的输入** 分类，不按游戏名词堆砌。

| 场景 | 人在干什么 | 焦点（算 B* 用） | 意图 | 开火 |
|------|------------|------------------|------|------|
| **定位 / 预瞄** | 还没看见人，准星放在「他最可能出头」的高度和墙沿 | 世界里的预瞄点（常见：头高、离墙沿一个身位） | `Hold` | 通常不开；预开火另说 |
| **Peek / 探头** | 自己平移过墙角，用身体把视线甩出来 | 先是预瞄点；看见人后改成目标 | `Peek` → 看见后 `Acquire` | **急停后** 才点第一枪（步枪） |
| **肩探 / 轻探** | 只露出一点点，收集信息 | 预瞄点 | `Peek`（行程短） | 常不开火 |
| **宽探** | 走得更开，自己造成的视角变化更大 | 同上，但眼睛位移更大 | 同上 | 急停或边走边扫（枪种决定） |
| **Jiggle / 晃探** | 来回小幅平移骗信息或骗开枪 | 预瞄点来回切 | `Peek` 循环 | 多半不开 |
| **甩枪 Flick** | 看见静靶或突然出现的靶，一次挥过去点 | 目标（静靶超前=0） | `Acquire` → `Flick` | 开火门：在靶上且够慢 |
| **跟枪 Track** | 粘在移动靶上连打 | 目标 + 短超前 | `Track` | 粘键：在靶上按着 |
| **转火 Transfer** | 干掉一个 / 换更高优先级，立刻瞄下一个 | **新**目标（旧的作废） | `Transfer` | 点射则再甩再点；扫射则不停扣、准星横拉 |
| **扫射转移** | 还在连发、后坐力没回零，准星挪到下一个 | 新目标 − **当前已积累的后坐力** | `Transfer` 但内环保持跟 | 一直按着 |
| **压枪 Recoil** | 枪自己抬，手往回拉 | 目标 − 后坐力表 | **不是独立意图**，是 B* 上的一层 | 已在开火 |
| **点射 / 点射转火** | 打一发、等准星回正、再打或再甩 | 目标 | `Flick` 循环 | 每发都过开火门 |
| **急停点射** | 先把水平速度刹住，再开枪（第一发准） | 目标或预瞄点 | `Peek`/`Hold` 结束瞬间 | **速度门**：水平速度≈0 |
| **微修正 / 拉枪** | 已经在靶附近，小小修 | 目标 | `Flick` 的第二段，或软 `Track` | 开火门 |
| **动靶上的甩** | 先甩到它 **将要到** 的地方，再改跟 | 带超前的目标 | `Flick` → 落地后 `Track` | 先点或直接粘 |
| **人动靶静** | 补偿自己走位 | 静靶，但每帧用新眼睛位置 | `Track`（相对运动来自自己） | 看枪法 |
| **双动** | 跟球又补自己的脚 | 相对运动 | `Track` | 看枪法 |
| **垂直跟 / 跳打** | 误差主要在 pitch | 同跟枪，速度估垂直分量 | `Track` | 粘键 |
| **空中** | 自己在跳，准星更晃 | 相对运动含自己的竖直速度 | `Track`，允许更大误差 | 步枪常不准，可故意打不准 |
| **预开火** | 人还没完全露头就打出头位置 | 预瞄点 | `Hold`/`Peek` | 时间窗到了就打，不要求看见 |

还有一些 **不是准星控制器的活**，不要塞进瞄准模型，另做策略层：

- 何时 peek、往哪走、何时停步、打完要不要撤
- 选哪个目标（血量、距离、威胁）——只把「当前主键」交给瞄准
- 换弹、切枪

**原则：** 走位改变的是眼睛位置；选靶改变的是焦点 ID；枪改变的是后坐力表和开火节奏。准星那只「手」始终只追 B*。

## 2. 推荐架构（这一套吃所有场景）

四层，从上到下。假人以后就按这个拆模块。

```text
┌─────────────────────────────────────────────────────────┐
│ 策略层（以后再做）：走位、peek 时机、选靶、要不要预开火   │
└───────────────────────────┬─────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 意图层：Hold / Peek / Acquire / Flick / Track / Transfer │
│         小状态机 + 反应时，不要一上来就神经网络          │
└───────────────────────────┬─────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────┐
│ B* 合成：预瞄点或目标 → 相对朝向 → 可选超前 → 减去后坐力 │
└───────────────────────────┬─────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 人手内环：误差大 → 急动度甩；误差小或在跟 → 弹簧 PD      │
│         + 有色噪声 + 间歇重规划（随机运动时）            │
└───────────────────────────┬─────────────────────────────┘
                            ▼
┌─────────────────────────────────────────────────────────┐
│ 开火门：看见 / 在靶 / 够慢 / 急停 / 粘键 / 预开火窗      │
└─────────────────────────────────────────────────────────┘
```

后坐力 **永远不是第五种意图**，它只改 B*。Peek **不是一种新的跟枪公式**，它是「人在动的 Hold，看见之后再 Acquire」。

---

### 2.1 感知（每一帧）

假人允许用的信息，要尽量接近「屏幕上能看到的」，不要开图：

| 输入 | 用途 | 像人的约束 |
|------|------|------------|
| 眼睛位置、当前 yaw/pitch | 算视线 | 真值可用（这是自己的身体） |
| 自己水平速度、是否在停步 | peek、急停开火 | 真值可用 |
| 可见目标的位置、半径 | 焦点、开火门 | **看不见的不要当看见**（墙后、屏幕外） |
| 目标画面位置的近期序列 | 估相对角速度 | **不要读引擎里的真实 velocity** |
| 已开了几发、是否按着火 | 后坐力表下标 | 真值可用 |
| 刚击杀 / 焦点 ID 变了 | 转火 | 事件 |

「可见」= 射线能打到、且大致在视野锥里。Peek 时目标从不可见变成可见，这是 `Acquire` 的触发器。

---

### 2.2 意图状态机

```text
                    看不见人
                 ┌──────────┐
                 │   Hold   │  定位：B* = 预瞄点，手几乎不动
                 └────┬─────┘
          自己开始平移过角 │  看见目标
                         ▼         ▼
                    ┌───────┐  ┌──────────┐
                    │ Peek  │─▶│ Acquire  │  愣 reaction_ms
                    └───────┘  └────┬─────┘
                                    │
                    ┌───────────────┼───────────────┐
                    ▼               ▼               ▼
              误差大、靶相对静   靶在动 / 人在动    焦点 ID 变了
                    │               │               │
                    ▼               ▼               ▼
                 Flick           Track          Transfer
              （急动度+修枪）    （PD+可选超前）   （短反应后
                    │               │            再进 Flick 或 Track）
                    └───────误差变小 / 甩完 ──────┘
                                    │
                                    ▼
                                 Track 或 Hold
```

切换规则（先写死，有数据再用 AI 1 填数字）：

| 从 → 到 | 何时 |
|---------|------|
| 任意 → Hold | 没有可见目标，也不在探头 |
| Hold → Peek | 策略层说「开始平移过角」，或自己水平速度明显且靠近掩体 |
| Hold/Peek → Acquire | **本帧目标从不可见变为可见**，或误差突然超过大阈值 |
| Acquire → Flick | 愣够了，且相对角速度小（静靶、远靶、刚露头） |
| Acquire → Track | 愣够了，且相对运动明显（跟枪图、近距扫） |
| Flick → Track | 误差已经小，但目标还在动 |
| Flick → Hold | 点完、目标死了或消失 |
| 任意开火中 → 仍当前意图 | 后坐力只改 B*，不切状态 |
| 任意 → Transfer | 击杀、或选靶层换成另一个可见目标 |
| Transfer | 再等 **较短** 的 `transfer_rt`（往往比第一次发现更短，人已经在枪战里），然后按误差走 Flick 或 Track |

**反应时不要全局一个数：**

- 第一次发现（从 Hold/Peek 进 Acquire）：最长，例如 150～280ms
- 转火：更短，例如 80～160ms
- 目标转向、自己起步导致误差炸开：几乎立刻重规划，但 PD 本身有滞后

这些分布从你的 `.shot` 直方图里取，不要写死成常数机器人。

### 2.3 焦点和 B*（场景差异主要在这里）

每一帧只选 **一个焦点**：

1. 有主键目标且可见 → 焦点 = 该目标中心（或头，若以后分部位）
2. 否则若在 Peek/Hold → 焦点 = **预瞄点**
3. 否则焦点 = 正前方很远的点（发呆，几乎不转）

预瞄点怎么来（定位 / peek 的灵魂）：

- 几何：掩体边缘外侧、常见头高（眼睛高度附近）、距离按地图/场景给一个「他会站哪」
- Shot 训练图：可以用目标刷新区域的中心、或上一发目标消失的位置
- 不要把预瞄点钉在屏幕正中 —— 人会把准星贴在 **出角那条竖缝的头高**，不是屏幕几何中心

然后：

```text
朝向 = 从眼睛指向焦点    // 人一走，即使焦点钉在墙上，朝向也会变

若意图是 Track，或 Flick 打的是动靶：
    用「焦点在画面上最近怎么挪」估相对角速度   // 禁止读真速度
    朝向再沿该速度超前 τ
        固定匀速：τ ≈ 50～100ms
        随机运动：τ ≈ 0～40ms 或关掉
        静靶 / 纯定位：τ = 0

若正在连发且有后坐力：
    B* = 朝向 − 后坐力表[已开了几发]
否则：
    B* = 朝向
```

这样：

- Peek 时人在走、焦点还是墙缝预瞄点 → 自动变成「人动靶静」的补偿，不必新公式
- 转火时焦点 ID 一换，B* 立刻指向新目标；若还在扫射，表不清零，就是扫射转移
- 压枪不必另写一套甩枪

---

### 2.4 人手内环（所有场景共用）

误差 `e = B* − 当前朝向`（注意角度要走短弧，左右不要转 350°）。

```text
若 |e| > θ_flick  且 意图是 Flick 或 Transfer 后的点射：
    用 Fitts 决定时长 T
    主路径：最小急动度（钟形速度）
    可略过冲，再接一小段二次修正
    中距可加一点弓形
    找不到历史邻居时用公式；静靶甩枪有数据后改检索扭曲

否则（Track、Peek 补偿、压枪连发、扫射转移、微修正）：
    弹簧 / PD：加速度 = k·e − c·速度
    匀速可预测：k 可稍硬
    随机 / 双动 / 空中：k 要软、加角速度上限，允许跟丢
    随机运动再套一层间歇规划：100～180ms 才改意图，误差炸开则立刻改

全程叠很浅的有色噪声（跟稳时更小）
状态切换时用短急动度过渡，禁止瞬移
```

**为什么甩和跟要两种外形：** 一次有把握的挥臂接近最小急动度；粘虫子接近带阻尼的弹簧。强行只用 PD 去甩，速度峰会不像甩臂；强行用整段贝塞尔去跟，B* 一变路径就穿帮。

有足够跟枪录像之后：内环可换成「PD 骨架 + 逐步行为克隆学残差」。不要用整段检索去跟，也不要用纯 RL。

---

### 2.5 开火门（定位 / peek / 点射的关键在这里）

瞄准再像，乱开枪也会假。按枪法和意图选门：

| 模式 | 条件（可叠加） |
|------|----------------|
| 点射（静靶、远距、第一发） | 焦点可见（或预开火窗）且误差在靶内且角速度够小，再额外等 20～60ms |
| 跟枪粘键 | 在靶上就按下；离开后延迟几十毫秒再松开（人会拖一发） |
| **急停门（peek 步枪）** | 自己水平速度低于阈值，或「开始刹车后经过 50～90ms」 |
| 预开火 | 时间到达「他将要出头」的窗，不要求可见；打完若没人就停 |
| 扫射 | 第一发过点射门，之后按着，直到换弹、目标死、或策略层松手 |
| Esc / 中途退出 | 不计入训练记录（产品已有规则，假人不必管） |

没有急停门的 peek 假人，会边跑边点得像开了移动命中补偿。

### 2.6 历史数据在这套架构里干什么

| 阶段 | 学什么 | 不要学什么 |
|------|--------|------------|
| 现在就能做 | 反应时、转火反应时、Fitts a/b、过冲、PD 的 k/c、噪声幅度、压枪延迟和拉够百分比、急停后多久开枪 | 不要端到端生成整局鼠标 |
| 静靶甩枪数据多了 | 检索相似甩枪片段，旋转后播放 | 不要检索整段跟枪 |
| 跟枪 / peek 补偿数据多了 | 逐步 BC 学 PD 之后的残差（你的滞后和搓） | 不要让网络同时发明弹道和走位 |
| 有官方弹道 | 后坐力用表 | 不要用扩散模型生成压枪 |
| 研究用 | 扩散、RL | 不要当产品默认；RL 无约束会锁头 |

切数据时按意图切，不要一锅炖：甩枪段、跟枪段、转火段、peek 急停段、压枪段。混在一起，模型会在静靶上自己抖出跟枪。

## 3. 每个场景怎么走这一套（对照用）

### 3.1 定位

意图 `Hold`。B* = 头高预瞄点。内环几乎锁住，只留极小噪声（人会微微晃，但准星会贴在出角）。不开火。看起来「没在瞄准」，其实一直在瞄一个空点。

### 3.2 Peek（含肩探、宽探、jiggle）

策略层给出平移；意图 `Peek`。焦点仍是预瞄点，因为人往往 **先把准星放好再探**。眼睛一动，B* 变，内环用软 PD 补偿 —— 和「人动靶静」完全同一条路。

- 肩探：位移小，可能全程不可见，然后缩回去（`Peek` → `Hold`）
- 宽探：位移大，补偿更大；看见人后 `Acquire`
- Jiggle：预瞄点不变，眼睛左右小抖，准星相对世界点修

看见敌人：加发现反应时，再 `Flick` 或 `Track`。步枪第一发走 **急停门**。

### 3.3 甩枪

静靶、刷新球、远点爆头：`Acquire` → `Flick`。B* 超前=0。二次修正 = 微拉枪。开火走点射门。

### 3.4 跟枪（匀速 / 随机 / 人动 / 双动 / 跳）

全部 `Track`。差别只在 τ 和 k：

- 匀速：短滤波 + 50～100ms 超前，PD 可稍硬
- 随机：τ≈0，k 软，间歇规划，允许跟丢
- 人动 / peek 补偿：每帧用新眼睛位置；滤波的是相对运动
- 双动：相对速度 = 估到的目标画面速度（已含自己的走）
- 跳打：误差在 pitch 上，同一套 PD；空中可把开火门加严或故意更软

### 3.5 转火

焦点 ID 切换 → `Transfer` → 短反应。然后：

- 已经松键 / 点射：当一次新的 `Flick`（可带动靶超前）
- 还在按着扫：不要回 Hold、不要清后坐力表，直接 PD 去新的（B* = 新目标 − 当前表），这就是扫射转移

转火最假的两种做法：瞬移到下一个球；或者把后坐力清零再当第一发甩。

### 3.6 压枪

不开新状态。连发时 B* 减表；人有 30～80ms 拉枪延迟和 90%～110% 幅度误差。随机弹道：表只减平均，剩下当扰动让 PD 去搓。换枪 = 换表，手的 PD 可留。

### 3.7 动靶上的甩、点射循环

大误差 + 相对运动 → 先对 **超前点** 做 `Flick`，落地后切 `Track`。点射循环 = 多次短 `Flick`，每发等开火门（和后坐力回正，若有）。

### 3.8 预开火

`Hold`/`Peek` 上焦点仍是预瞄点。开火门不要求可见，只要求时间窗。打空就停，不要开始「跟空气」。

## 4. 在 Shot 里分阶段落地（仍是同一套，不是五套产品）

当前训练图还是静球点射。下面每一步都往第 2 节的架构里填插件，不要分叉出无法合并的假人。

| 阶段 | 打开什么 | 对应现在能练的 |
|------|----------|----------------|
| **P0** | `Acquire`+`Flick`+点射开火门+噪声；目标可见则焦点=球 | 现在的静球 60 秒 |
| **P1** | 意图机 + `Track` PD + 相对速度估计 + 超前 | 以后固定速 / 随机跟枪图 |
| **P2** | `Transfer` + 转火反应时；击杀后换焦点 | 多球、六目标转火 |
| **P3** | 玩家位移进 B*；`Hold`/`Peek` 预瞄点；急停开火门 | 走位跟枪、peek 图 |
| **P4** | 后坐力表叠进 B*；扫射转移自然出现 | 压枪、扫射转移 |
| **P5** | AI 1 填全部分布；静靶检索；跟枪 BC 残差 | 更像「你的手」 |

P0 不要上逐步网络和扩散。P1 不要检索整段跟枪。P4 不要用 WindMouse 的「风」冒充后坐力。

## 5. 跟枪四种差别、后坐力分层（零件背景）

跟枪不是一种，但对上面的内环来说只改 **B* 和软硬**：

1. **固定方向、固定速度** — 可超前；熟练后误差很小。
2. **随机方向、随机速度** — 预测只能看很短；故意保留滞后和跟丢。机器贴死一眼假。
3. **目标不动，人物动** — 补偿自己的移动；B* 必须用当前眼睛位置重算。Peek 属于这一类的特化（焦点暂时是预瞄点）。
4. **两边都动** — 画面上的相对运动；预测用相对速度。停步再打是策略层。

后坐力拆两层，永远不要和「手」焊死：

```text
瞄准用的目标朝向 = 指向焦点的朝向  −  当前已经积累的后坐力朝向
```

有官方表就减表；没有表就用历史估「第 n 发平均抬多少」当经验表。记录以后若加枪：每一发要记下后坐力增量，否则回放对不齐。

## 6. 纯算法零件（不训练也能跑）

没打过局也能跑。有历史时，用统计数字填进公式。下面每个零件仍标：甩 / 跟 / 压适不适合。定位、peek、转火请对照第 3 节：它们是 B* 和意图，不需要新公式。

---

### 算法 1 — 直线匀速（对照，不要当成品）

**干什么。** A 到 B 匀速走完。

**原理。** 最短路径。人手有加速减速，跟枪时也不会用恒定角速度死贴。

**优点。** 最短对照；必到 B。  
**缺点。** 一眼假。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 仅当机器下限 | 完全不行（B 一直变） | 不行 |

---

### 算法 2 — 缓入缓出（smoothstep）

**干什么。** 仍走直线，进度 S 形：两头慢、中间快。`s = 3τ² − 2τ³`。

**原理。** 肌肉不能瞬间拉满或刹死，像电梯启停。

**优点。** 比匀速像；必到 B。  
**缺点。** 路径太直；速度峰太对称。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 可当甩枪骨架 | 不适合（一次规划走完） | 不适合单独压连续后坐力 |

---

### 算法 3 — 最小急动度（Minimum Jerk）

**干什么。** 进度用 `s(τ) = 10τ³ − 15τ⁴ + 6τ⁵`。这是「在给定时间从 A 到 B，加速度变化尽量小」的经典曲线，真人一次有把握的指向经常接近它。

**原理。** 一次甩臂的宏观形状：中间最快、两头最软。

**优点。** 有实验依据；可复现。  
**缺点。** 太干净；默认只有一段，没有修枪。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| **Flick / 转火点射的主弹道** | 整段曲线不行；可改成间歇小段（算法 13） | 单次拉枪可以；连发要用一串短急动度去追「目标 − 后坐力」 |

---

### 算法 4 — Fitts 定律（只管甩多久）

**干什么。** `T = a + b · log₂(D/W + 1)`。D 多远，W 目标多大。人不是距离加倍时间加倍。

**优点。** 专治「机器 80ms 甩完」；可插在几乎所有甩枪前面。  
**缺点。** 不管形状；极近要设时间下限。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 标配 | 不直接用。目标突然转向 / 转火时，可用一次小 Fitts 决定「追上去花多久」 | 每一发压多少时间不像 Fitts |

---

### 算法 5 — 两段式：主弹道 + 二次修正

**干什么。** 先粗甩到 B 附近（可略过冲），再一小段修到位。人先开环大动作，再看着用闭环微调。

**优点。** 像人的关键；可调「修不修枪」。  
**缺点。** 两段接太死会像停顿。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 静止靶、转火点射、peek 露头后的第一下 | 不适合整段跟；转向瞬间可以当「重新甩过去」 | 开镜第一发可用；连发不要每发都完整两段 |

---

### 算法 6 — 弹簧 / PD 追踪（跟、peek 补偿、扫射转移的内环）

**干什么。** 准星是滑块，B* 是弹簧另一头：拉力 ∝ 误差，阻力 ∝ 速度。每步 `加速度 = k·误差 − c·速度`。

**原理。** 手臂有惯性和阻尼。闭环：B* 变了就改追。阻尼大则稳，小则过冲。

**优点。** 天然适合跟枪、换靶、人移动、peek 补偿、压枪连发。参数少。  
**缺点。** 太硬=锁头，太软=跟不上；默认偏「先快后蹭」，和甩枪的钟形速度不完全一样。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 能用但外形不如急动度 | **四种跟枪 + peek 时补自己脚步 的默认内环** | 误差改成「目标 − 后坐力」即可；k 不要过大 |

跟随机运动时：把 k 调小、加上限速，让它跟不住突变——这是特性不是 bug。

---

### 算法 7 — WindMouse（重力 + 风）

**干什么。** 往目标拉（重力）+ 缓慢变化的随机推力（风）。靠近时减小风。

**原理。** 人手抖是「这一帧和上一帧相关」的，不是雪花点。

**优点。** 路径有活的弯折。  
**缺点。** 参数多；容易围着 B 转；更像桌面拖文件。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 当扰动层 | 风会破坏粘靶，跟枪时风力要很小 | 不要用风去「模拟后坐力」（后坐力有方向，不是无方向的风） |

---

### 算法 8 — 有色噪声（叠在任何方案上）

**干什么。** 干净路径上加有记忆的小抖动：`n ← 0.9n + 0.1·高斯`。靠近目标或正在跟稳时减小。

**优点。** 补人味；幅度可从历史高频量出来。  
**缺点。** 不能单独当方案。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 要加 | 要加，但更小 | 不要替代压枪；可叠在压枪轨迹上当手抖 |

定位时噪声要更小，否则预瞄点会在墙缝上乱晃，不像在「架枪」。

---

### 算法 9 — 贝塞尔弧

**干什么。** A、B 之间插控制点，走轻微弓形（关节是转的）。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 中等距离甩枪好用 | 跟枪路径由目标决定，不要额外绕大弯 | 无直接关系 |

Peek 补偿不要加弓形；那是自己平移造成的视角变化，不是挥臂弧。

---

### 算法 10 — 反应时 + 开火门

**干什么。** 球出现后先愣着；开火要求「已经在靶上 + 速度够慢 + 再等几十毫秒」。跟枪连发则改成：在靶上就按着，离开靶就松开（可加一点延迟）。Peek 再加急停门。

**原理。** 人不是像素碰到边缘就按下。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 强制 | 改成「在靶上保持开火」，仍要一点滞后 | 第一发仍用开火门；连发后坐力开始累积 |

转火用 **更短** 的反应时，不要和「从架枪到发现」用同一个分布。

---

### 算法 11 — 超前瞄准（Lead）

**干什么。** 不瞄准焦点 **现在** 的位置，而瞄准「它若保持当前速度，Δt 之后会到的位置」。Δt 约等于你的反应 + 转动时间，跟枪里常用 30～120ms。

**原理。** 光有延迟。你转到「刚才看见的点」时，匀速目标已经走了。固定速度跟枪几乎必加；随机速度只能用很短的 Δt。

**优点。** 匀速跟枪立刻稳很多。  
**缺点。** 目标一转向，超前变成帮倒忙。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 静靶 Δt=0；动靶上的甩要对超前点甩 | **固定速度强烈推荐**；随机跟枪用短 Δt 或关掉 | 后坐力不是目标运动，不要 lead 后坐力；用表减 |

---

### 算法 12 — 常速预测 / 简单滤波（「猜它下一步」）

**干什么。** 记下焦点最近的角速度，当成短期内恒定。可用很浅的指数平均。随机运动时窗口要短。

**像人的要点：** 假人只许用「准星看到的位置序列」估速度，不要读内存里的真实 `velocity`。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 静靶不用 | 四种跟枪、peek 补偿都该有 | 有表时不必估后坐力速度 |

---

### 算法 13 — 间歇规划（人不是每毫秒都在最优控制）

**干什么。** 每 80～200ms 才重新决定「下一小段往哪甩」，中间按当前计划走。突然误差变大（目标转向、自己起步、转火）就提前重规划。

**原理。** 神经科学里的间歇控制：人一阵一阵发指令。跟随机目标时，这种「一顿一顿的修」非常像人。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 两段式就是间歇的特例 | **随机跟枪很推荐** | 连发时可每发或每 50ms 重算「目标 − 后坐力」 |

---

### 算法 14 — 后坐力表补偿（压枪专用）

**干什么。** 预先有一张表：第 1 发、第 2 发……枪口相对第一发抬了多少度。

`想看的方向 = 指向焦点 − 表[已开了几发]`

表上可加：延迟、幅度 90%～110% 的误差。

**优点。** 可解释、稳、和跟枪分层清晰。换枪只换表。  
**缺点。** 没有表就失效；随机弹道只能补平均。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 第一发通常无后坐力或很小 | 连发、扫射转移的标配外层 | **有表时的首选** |

---

## 7. AI / 统计零件（从历史里学）

不一定等于大模型。参数主要从 `.shot` 来，就算这类。

**切数据时按活分类：** 甩枪段、跟枪段、转火段、peek 急停段、压枪段。混在一起学，模型会在静靶上「自己抖出跟枪」，或在跟枪时突然做一次大 flick。

---

### AI 1 — 只学几个数填进算法（全场景第一优先）

学：Fitts 的 a、b；发现反应时；**转火反应时**；过冲；跟枪平均滞后；跟丢后修回来的时间；压枪延迟和拉够百分比；**急停后多久开枪**；开枪落点在靶上的分布。

**优点。** 最稳、能解释、几十局就有直方图。  
**缺点。** 学不到独特曲线形状。

这是第 2 节架构的默认学习方式：状态机还是人写的，数字变成「你的」。

---

### AI 2 — 检索历史片段，旋转后播放

把过去「相似的一段」转方向再播。

**优点。** 细节是真的；几乎不用训练。  
**缺点。** 整段开环。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| **静靶甩枪首选学习方案** | **基本不适合**（含 peek 补偿、随机运动） | 可检索「第 n 发附近的压枪片段」，连发节奏要对齐 |

跟枪、peek、转火扫射都不要硬用检索整段。最多检索「突然转向后的 200ms 修枪」当短补丁。

---

### AI 3 — 平均速度剖面

按「这一枪走了百分之几」平均你的速度山峰。

| 甩枪 | 跟枪 | 后坐力 |
|------|------|--------|
| 可替代通用急动度 | 跟枪没有统一进度轴，不适合 | 可对「第 n 发后 100ms 内的下压力」做平均剖面 |

---

### AI 4 — 检索 + 小网络残差

骨架仍是检索，网络补没见过的距离。只适合静靶甩枪进阶。

---

### AI 5 — 逐步模仿（行为克隆）——跟枪 / peek 补偿的 AI 主力

每一步看：误差、焦点最近怎么动、自己最近怎么动、是否在扫射、后坐力累计、是否在急停 → 预测下一步鼠标。用你的历史当标准答案。

**优点。** 能换靶、能跟人动、能学你跟随机目标时的滞后。  
**缺点。** 会累积误差；要较多数据；太确定像机器人。

推荐用法：PD 先能跑，网络只学残差。不要让网络同时发明弹道和「何时 peek」。

---

### AI 6 — 整段生成（VAE / 扩散）

一次画出整条曲线。跟枪时长不定、peek 条件是整段走位+目标轨迹，数据极难。不要当第一方案。

---

### AI 7 — 强化学习

命中给奖。无模仿约束会变成锁头、完美压枪、完美预瞄。只适合研究，且必须行为克隆打底 + 限制最大角速度 + 故意滞后。

## 9. 为什么是「一套状态机」，而不是「每个场景一个模型」

1. **问题结构相同。** 所有场景都是追 B*。场景只改焦点从哪来（预瞄点 / 当前靶 / 新靶）、B* 变多快、何时许开枪。
2. **Peek 不是新瞄准。** 它是定位 + 自己平移 + 看见之后的一次发现。漏算眼睛位置才会看起来像新问题。
3. **转火不是新瞄准。** 它是换焦点 + 更短反应时；扫射转移只是换焦点时 **不清后坐力表**。
4. **压枪不是新瞄准。** 它是 B* 减表。和跟、甩、转火正交，可以叠。
5. **跟枪杀死了检索。** 检索依赖「整段未来长得像历史某段」。随机运动、走位、peek 几乎不会重演。
6. **随机跟枪的「像人」= 不完美。** 把 PD 调到贴死，或让 RL 贴死，都是失败。
7. **单一大模型看起来省事。** 数据种类一多（静靶、跟枪、探头、扫射）就会哪种都不像；还无法换枪、换图。
8. **AI 的性价比。** 统计填参立刻有用；检索仅给静靶甩枪；逐步 BC 留给跟枪和 peek 补偿；扩散和 RL 成本高、还容易更不像人。

人手不是更平滑的直线，也不是完美雷达锁。它是：**会在墙缝上架着、会探头、会愣、会甩过、会急停再点、会粘不紧、会跟丢再修、会转火慢半拍、压枪会慢半拍。**

算法负责骨架和物理（含人物位移、预瞄几何、弹道表）；状态机负责「现在在干哪类活」；历史数据负责把滞后和抖动变成「你的手」。
